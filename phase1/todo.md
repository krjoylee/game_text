## 🟡 [Phase 2] 이미지 엔진 가독성 혁신 & 팔레트 컬러화 (Image & Clarity)

> **핵심 과제**: 현재의 흑백 점자/블록 도트는 터미널에서 여전히 형태 인지도가 낮음.  
> 고전 게임(NES/PC-98)이 1MB 안에서 16색 팔레트로 선명한 비주얼을 뽑아낸 방식을 터미널에 이식한다.

- [ ] **IMG-01** **고전 게임 16색 인덱스 팔레트(Color Palette) ANSI 렌더링 시스템 도입**
  - **문제**: 흑백 도트로는 배경, 인물 얼굴, 의복, 사물이 서로 엉켜 시각적 분리가 안 됨.
  - **해결/목적**: 16가지 기본 컬러 팔레트(피부색, 갓/수염, 의복색, 배경색 등)를 정의하고, 도트마다 ANSI 전경색/배경색 코드를 매핑하여 1바이트 수준의 극소 용량 증가만으로 폭발적인 인물 구분감 확보.
- [ ] **IMG-02** **Sobel/Canny 외곽선 보존 융합 알고리즘 (Edge-Preserving Contrast)**
  - **문제**: 명암만으로 도트를 찍으면 얼굴의 코나 턱선, 모자 테두리가 배경 톤에 묻힘.
  - **해결/목적**: 인물 외곽선(Edge)을 최우선 비트로 고정하고 내부만 명암 채우기를 수행하여 어떤 터미널에서도 실루엣이 한눈에 보이도록 개선.
- [ ] **IMG-03** **캐릭터 시트(Character Visual Spec) 기반 인물 중심 스프라이트 생성기**
  - **문제**: 풍경이 배경에 너무 많이 들어가 정작 중요한 주인공의 표정과 감정이 작아짐.
  - **해결/목적**: 23줄 캔버스의 좌우 60% 영역을 인물 상반신/얼굴 클로즈업(Portrait) 전용으로 할당하고 배경은 10~20% 실루엣으로 극단적 단순화.
- [ ] **IMG-04** **AsciiArt Studio 웹/GUI 실시간 프리뷰 뷰어 구축**
  - **문제**: 터미널에서 매번 실행해봐야만 결과물을 볼 수 있어 임계값(Threshold/Contrast) 조절이 비효율적임.
  - **해결/목적**: 슬라이더로 대비와 엣지를 실시간 조절하며 최종 터미널 렌더링 형태를 즉시 검증하는 경량 프리뷰 도구 제작.

## 🔵 [Phase 3] 게임 엔진 경량화 & 렌더러 정밀 튜닝 (Engine & Optimization)

> **핵심 과제**: 1MB 이하의 단일 바이너리 용량을 철저히 방어하면서 화면 표현력 극대화.

- [ ] **ENG-01** **ANSI 16색/256색 컬러 버퍼 지원 (`ScreenBuffer` 확장)**
  - **문제**: 현재 `Cell` 구조체는 문자(`ch`)만 저장하여 흑백 텍스트만 렌더링 가능.
  - **해결/목적**: `Cell`에 `fg_color: u8`, `bg_color: u8` (각 1바이트)를 추가하여 40줄 전체 화면의 색상 정보를 깜빡임 없이 동시 출력.
- [ ] **ENG-02** **터미널 환경별 전각/반각 폰트 칼각 오차 보정 (UI-01 재정비)**
  - **문제**: Windows Terminal, ConHost, WSL, macOS 터미널마다 점자/특수기호의 자폭(Display Width) 렌더링 미세 오차 존재.
  - **해결/목적**: 자폭 계산 테이블(`width.rs`)을 보강하고 프레임 우측 테두리선(`║`) 밀림 현상을 완벽 방지.
- [ ] **ENG-03** **6프레임 시네마틱 애니메이션 프레임 데이터 RLE(Run-Length) 압축**
  - **문제**: 6개 프레임을 통째로 YAML에 넣으면 파일 줄 수가 수백 줄로 팽창함.
  - **해결/목적**: 반복되는 공백과 도트를 압축(RLE) 파싱하여 팩 파일 용량을 1/5 수준으로 경량화.
- [ ] **ENG-04** **씬 전환 사운드 효과(BEEP/Bell / Chiptune) 미니멀 프로토타입 검토**
  - **목적**: 고전 레트로 감성을 위해 터미널 벨(`\x07`) 또는 100KB 미만의 단일 경량 오디오 재생 기능 모색.
